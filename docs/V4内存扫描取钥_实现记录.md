## 核心结论

1. **微信 4.x 静态链接 WCDB/SQLCipher**，主模块 = `Weixin.dll`（~188MB，仅 ~117 个导出），
   `sqlite3_key_v2` 无导出符号 → 无法按符号 hook。
2. **每个账号有独立密钥**。当前微信登录/活跃的账号，其密钥存在于进程内存（可扫描）；
   非活跃的历史账号密钥**不在内存中**（V4 扫描找不到）。
   - 实测：账号 A（其密钥值已从本记录中清除）能解该账号全部库；
     账号 B（`wxid_<已隐去>`）是**另一个密钥**，V4 扫描取不到（未活跃加载）。
3. **微信版本**：本机为 `4.1.13.x`（Weixin.dll 在 Windows 程序目录 `…\Tencent\Weixin\4.1.13.x\Weixin.dll`）。

## 取钥算法（V4，自包含实现）

流程 = 提取 internal_db_key + 内存扫描 + XOR + HMAC 校验。

### 步骤1: 从 Weixin.dll 提取 internal_db_key（`core/wx4/dll_key_v4.py`）
- **自写 PE 解析器**（无 pefile）：解析 DOS/PE/可选头，定位代码段（`SCN_MEM_EXECUTE=0x20000000`）。
- 代码段中扫描机器码序列，正则：
  ```
  \x48\xBA <8B>   ; mov rdx, imm64 (group1)
   [3-8 bytes any]
  \x48\xBA <8B>   ; mov rdx, imm64 (group2)
   [3-8 bytes any]
  \x48\xBA <8B>   ; mov rdx, imm64 (group3)
   [3-8 bytes any]
  \x48\xBA <8B>   ; mov rdx, imm64 (group4)
   [3-8 bytes any]
  \x48\x85\xC0    ; test rax, rax
  ```
- 4 个 imm64 拼接 = 32 字节 internal_db_key 候选。
- **实测 0.4s 提取到 2 个候选**（internal_db_key 候选值已从本记录中清除）：

> 注意：旧 `dll_key_scan.py` 用 pefile 扫 `.rdata`（stride=32）**找不到**（0 候选）。
> 正确方法是**扫代码段 mov rdx 机器码模式**，不是扫 .rdata。

### 步骤2: 内存扫描 GetKeyAddrStub（`core/wx4/v4_key.py`）
- YARA 规则特征（纯 Python 字节替代）：`{ ?? ?? ?? ?? ?? ?? 00×10 20 00×7 2f 00×8 }`（33 字节）。
- 固定部分 `FIXED_PART` = 偏移 6 开始的 27 字节：`00×10 | 0x20 | 00×7 | 0x2f | 00×8`。
- 匹配后在**特征起始 offset** 读取 8 字节指针（参考项目逻辑：`read_num(memory, offset, 8)`）。
  - 实测为 48 位私有 heap 地址，特征前 8 字节小端即指针（地址值属运行期临时数据，已隐去）。
- 从指针地址读 32 字节候选 → `_is_potential_key` 熵过滤（唯一字节≥15、可打印≤24）。
- **用 ctypes `VirtualQueryEx`+`ReadProcessMemory`**，无 pymem。

### 步骤3: XOR + HMAC 校验（关键修正点）
- SQLCipher4 参数：`KDF_ITER=256000`，`MAC_ITER=2`，SHA-512。
- `page_key = pbkdf2_hmac('sha512', raw_key, salt, 256000, 32)`
- `mac_key = pbkdf2_hmac('sha512', page_key, salt^0x3a, 2, 32)`
- **`stored_hmac` 在页面末尾保留区**：`page[PAGE_SIZE-80+16 : PAGE_SIZE]`（64 字节）。
  - ❌ **错误**：用 `page[16:80]`（页面头部）—— 这是之前 V4 扫描失败的根因。
  - ✅ **正确**：HMAC 覆盖 `page[offset:cipher_end]` + 页码（offset=16 跳 salt，第一页）。
- 若提供 internal_db_key：`raw_key = candidate ^ internal_db_key`（对每个候选尝试）；未提供则直接以 candidate 验证。

## 验证结果

- 对活跃账号（`<账号>_effe/message_0.db`）：**1.5s 取到密钥**（HMAC 完全匹配，密钥值已隐去）。
- 修正 HMAC 位置前的旧 `v4_scan.py`（`PBKDF2(...,2)` + 错误 hmac 位置）**全部失败** → 已废弃。
- 参考项目 `key_v4.is_ok` 用 `PBKDF2(passphrase, salt, 32, 256000)` + `mac_key=PBKDF2(new_key, salt^0x3a, 32, 2)`，HMAC 存页面尾部。
