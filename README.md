# 绿泡泡聊天记录总结

面向客户成功团队的沟通归档工具。选客户 → 选时间 → 一键生成沟通总结 → 存进 Excel。
全程图形界面操作，不需要任何编程或命令行基础。

数据来源支持**微信 4.x 本地数据库直读**（Windows / macOS）、导出的聊天记录文件，
以及内置样例数据 —— 详见第三节。

---

## 一、最快上手（3 步）

1. 双击 **`绿泡泡聊天记录总结.exe`**（真正的单文件可执行程序，无需安装 Python，双击即用；若没有 exe 或想用 Python 启动，可双击 `绿泡泡聊天记录总结.bat`）
2. 数据来源保持默认的 **「内置样例数据」**，点「加载聊天对象」→ 勾几个 → 点「开始提取并生成总结」
3. 看一眼弹出的 Excel，确认产出格式符合你的归档要求

样例数据跑通后，再切到真实数据源（见第三节）。

## 二、界面六步

| 步骤 | 做什么 | 说明 |
|---|---|---|
| ① | 选择聊天记录来源 | 四种方式，见第三节。**群聊务必填「我方成员」**（见下） |
| ② | 勾选聊天对象 | 支持搜索 + 多选。**搜索不会清空已勾选的对象**，可以「搜A勾上→搜B再勾上→一起生成」 |
| ③ | 设置时间范围 | 点「近 7 天」「本月」等按钮最省事，也可手填 `2026-08-01` |
| ④ | 选生成什么、怎么生成 | 上半是**生成内容**（两者都要 / 仅沟通总结 / 仅问题答复清单），下半是**生成方式**（智能 / 仅 AI / 仅本地）。选「仅问题答复清单」时字数与客户阶段会自动置灰——它们只影响沟通总结 |
| ⑤ | 设置 Excel 保存位置 | 建议用「追加」模式，长期累积到同一个台账文件 |
| ⑥ | 查看与修订结果 | 表格列会跟着④的选择切换。双击任意一行可改内容，改完点「导出到 Excel」再存一次 |

**每一个「聊天对象 + 时间范围」产出恰好一篇 50–200 字的独立总结，对应 Excel 的一行。**

### ① 里的「我方成员」——群聊必填

群聊里"我方"往往不止你一个人。同事用自己的号、或通过企微/OpenIM 桥接号发言时，
程序默认会把它当成"对方"，结果就是**答复大面积显示「未答复」**。

在 ① 区「我方成员」里填上你和同事的名字（逗号分隔），或点旁边的「选择…」：

- 窗口会**预填写**你已配置的成员（默认已勾上，配错了可以取消勾选）
- 点「开始扫描」会从已勾选的聊天对象里按行为找出其他同事，逐个给出**判断依据**
  （是不是企微桥接号、多少次紧跟在客户问句之后发言、多少次用我方口吻主动认领）
- **只给候选，不替你决定**——判定"谁是同事"是业务问题，猜错会把客户的话当成我方答复，
  比漏掉更难发现。核对依据后自己勾选即可

实测（某交付群近 60 天 687 条消息）：不填时 127 行里 95 行未答复；填了之后答复才真正对得上。

#### 名称库：同事名字存一次，以后只勾选

同一批同事每个季度都要重输一遍很烦，所以「选择…」窗口带一个**名称库**：

| 想做的事 | 怎么做 |
|---|---|
| 加人 | 「手动添加」输名字，回车或点「添加」；或用「导入 Excel…」 |
| 从 Excel 导入 | 选文件 → 选姓名所在的列（程序会自动猜，一般直接对）→ 核对预览 → 导入 |
| 导入大名单（整个部门/公司） | 在导入对话框里**取消**「导入后同时勾选为本次使用」 |
| 不知道表格该怎么填 | 点「**导出 Excel 模版**」，选保存位置，拿到一份空模版照着填 |
| 这次用谁 | 在表里勾选。**不勾只是这次不用，不会把人从库里删掉** |
| 真删人 | 选中那一行 → 「从名称库删除」 |
| 看库里有什么 | 窗口里显示「名称库：N 人」；命令行 `python cli.py config --show` |

「导出 Excel 模版」给出的模版长得这样，**必填的那列表头是红色的**：

| 姓名（必填） | 部门（可选） | 手机号（可选） | 备注（可选） |
|---|---|---|---|

只有「姓名」是必填，其它列随便填、导入时会自动忽略。模版故意**不放示例数据行**——
用户多半会直接填在示例下面，示例名字就被一起导进名称库了。
填写说明放在表头的**单元格批注**里（批注不是数据，不会被当成姓名读进去）。

库（长期存储）和 ① 区的「我方成员」（本次选用）是**两件事**：库是你认过的全部同事，
「我方成员」是这一次跑要算作我方的人。点「确定」时会把本次勾选的人存进库。

> **导入大名单时注意**：导入对话框里有个「导入后同时勾选为本次使用」，默认是勾上的。
> 如果你导入的是**本项目参与的同事**，保持勾选即可。但如果导入的是**整个部门/公司的
> 花名册**，请取消它——否则几十个人会全部变成「我方成员」，而「我方」认错了会让
> **客户的发言被当成我们的答复**，问答清单内容错配，比漏掉更难发现。
> 取消勾选后这些人只进名称库，要用时在表里勾上即可。

导入员工花名册不用担心串味：序号、部门、手机号、表头这些会被自动剔掉
（`张三`、`李四 交付` 这类人名会留下，`研发部`、`13800138000` 不会）。
手动输入的名字**不会**被自动过滤——你明确敲进来的名字应当尊重，
但如果看起来不像人名会提示你核对（名称库是按部分匹配判身份的，泛词可能误伤客户发言）。

### Excel 输出格式（固定三列，不多不少）

| 客户名称 | 时间范围 | 总结内容 |
|---|---|---|
| 张三 · 甲乙医药 | 2026-08-02 ~ 2026-08-31 | 期间共沟通 12 条消息，核心围绕审批流配置…… |

### 第二种输出：客户问题答复清单

除上面那篇「叙述式总结」，还可以把同一段时间整理成**一问一行的表格**：客户提了哪些问题、我们怎么答复和处理的。
两张表可以一次跑完，写进**同一个 Excel 的两张 sheet**，互不干扰。

| 客户名称 | 类型 | 提问时间 | 客户问题 | 我方答复/处理 | 答复时间 | 状态 | 原始记录 |
|---|---|---|---|---|---|---|---|
| 张三 · 甲乙医药 | 报错 | 09-06 16:40 | 但审批到第二级卡住了，说没有匹配的审批人 | 收到，是审批流里海南分组没绑对应审批节点。我同步给实施同事今晚修，明天上午给您结果 | 09-06 16:52 | 已答复 | 客户[09-06 16:40]：…… ‖ 我方[09-06 16:52]：…… |

- **类型**：`提问` / `需求` / `报错` / `投诉` / `我方待办`。
  加 `我方待办` 是为了把"我们自己认领了要做的事"也收进来；它没有客户提问，
  「客户问题」列显示 `—`。想只看客户提的，按这一列筛掉「我方待办」即可。
- **状态**：`已答复` / `未答复（待跟进）` / `已承诺（待跟进）`（后两类在表里标红/标橙）。
- **原始记录**：双方原话，用来核对抽取有没有改意思。不需要就隐藏这一列。

```bash
# 两者都生成（默认）
python cli.py run --source wx4 --all --preset 30d --out 台账.xlsx

# 只出问答清单 / 只出叙述总结
python cli.py run --source wx4 --all --preset 30d --out 台账.xlsx --output-format qa
python cli.py run --source wx4 --all --preset 30d --out 台账.xlsx --output-format summary

# 不知道群里的同事都叫什么？先让程序猜，你确认后填进「我方成员」
python cli.py suggest-self --source wx4 --contacts "某某客户交付群" --preset 30d
```

> **群聊必读**：群聊里"我方"往往不止你一个人。同事用自己的号（或企微/OpenIM 桥接号）
> 发言时，程序默认会把它当成"对方"，答复就会大面积变成"未答复"。
> 请用 `--self-names` 把同事的名字列上，例如
> `--self-names "李四,张三,王五"`（也支持部分匹配，填「张三」能匹配到备注「张三 交付」）。
> 不确定有哪些同事，用上面的 `suggest-self` 先列候选，它会给出发言次数和判断依据。
> GUI 里对应「我方成员」输入框。

### 名称库的命令行用法

命令行的导入与界面上那个按钮**语义一致：以文件为准**。

```bash
# 看当前名称库与本次选用名单
python cli.py config --show

# 手动加人 / 删人
python cli.py config --add-library "张三,李四"
python cli.py config --remove-library "李四"

# 导出模版（表头必填标红 + 把库里的人填进姓名列），改完再导回
python cli.py config --export-template "D:/同事名单.xlsx"
python cli.py config --export-template          # 省略路径 → 写到当前目录

# 按 Excel 更新名称库（自动猜姓名列；也可用 --sheet/--column 指定）
# 注意：文件里没有的人会从库里移除——和界面上一样
python cli.py config --import-library "D:/同事名单.xlsx"
python cli.py config --import-library "D:/同事名单.xlsx" --column 3

# 会删人时默认拒绝执行，先列出将新增/移除的名单；确认无误再加 --force
# （等价于界面上那个确认框）
python cli.py config --import-library "D:/同事名单.xlsx" --force

# 设置本次选用（库里留着不代表这次要用）
python cli.py config --self-names "张三,李四"
```

`suggest-self` 会把**名称库 + 本次选用**里的人都当成已知同事，不再重复推荐。

## 三、数据来源：请务必读这一节

微信的聊天记录存在本机一个**加密数据库**里，密钥在微信进程内存中。
本工具支持四种数据源，**上层功能完全一致，随时可切换**：

| 数据源 | 适用场景 | 稳定性 | 需要准备什么 |
|---|---|---|---|
| **内置样例数据** | 试用、培训、验收产出格式 | ★★★★★ | 无 |
| **本机微信 4.x 加密库直读**（Windows） | 日常生产使用（Windows 微信 4.x） | ★★★★☆ | 微信保持登录状态，首次使用需自动抓取数据库密钥（只读内存扫描，无注入、无重启、无网络外发） |
| **导入已导出的聊天记录文件**（推荐·跨平台） | 日常生产使用 | ★★★★☆ | 把记录导出成文件或 .zip 压缩包（导出途径由用户自行掌握） |
| **读取已解密的微信数据库** | 已有解密库的场景 | ★★☆☆☆ | 已解密的 `MicroMsg.db` + `MSG*.db`（或直接选整包 .zip 存档） |

### wx4 直读模式（Windows 微信 4.x 加密库）

自动探测本机已安装的微信 4.x、定位账号数据目录、读取加密数据库。**无需手动导出**，一键加载。

**首次使用流程：**
1. 确保微信已登录并处于运行状态
2. 在 GUI 中选择「直接读取本机微信（Windows 4.x）聊天记录」数据源
3. 点「加载聊天对象」→ 自动扫描内存获取密钥（无注入、无重启）并缓存 → 解密库 → 加载联系人
4. 密钥会被加密保存在本地（DPAPI 加密），后续使用无需重复抓取

**命令行模式：**
```bash
# 列出可用数据源（确认 wx4 可用）
python cli.py list-sources

# 抓取数据库密钥（需微信运行中）
python cli.py wx4-capture

# 加载联系人列表
python cli.py list-contacts --source wx4

# 生成总结
python cli.py run --source wx4 --all --preset 30d --out 总结.xlsx
```

**技术原理：**
- 只读扫描微信进程内存（ReadProcessMemory），定位数据库密钥
- 使用 SQLCipher4 参数（PBKDF2-SHA512 × 256000, AES-256-CBC）解密数据库
- 解密后的数据仅暂存于 `~/.wxcsm/wx4_staging/`，使用后自动清理
- 密钥通过 DPAPI 加密存储，仅本机当前用户可解密

### 导入模式的文件约定

选一个文件夹，**一个文件 = 一个聊天对象，文件名即客户名称**：

```
D:\客户沟通记录\
├── 张三 · 甲乙医药.csv
├── 壬癸信息×丙丁科技 项目群.txt
└── 赵敏 · 云图科技.json
```

三种格式都自动识别，列名不必完全一致（常见写法都认）：

- **CSV** — 需含时间列与内容列，如 `StrTime,Sender,StrContent,IsSender`
- **TXT** — 形如 `2026-08-20 09:30:00 张三:` 换行接内容，支持多行消息
- **JSON** — 数组，元素含时间与内容字段

### 合规提醒

提取客户沟通记录前，请确认已获得公司授权，并遵守个人信息保护相关规定与客户约定。
选择「仅用本地生成」时，聊天内容**不会离开本机**。

|---|---|

## 五、命令行入口（供自动化 / WorkBuddy 调用）

GUI 与 CLI 共用 `core/` 下同一套引擎，行为完全一致。

```bash
# 看有哪些数据源
python cli.py list-sources

# 列出可选聊天对象（支持关键词过滤）
python cli.py list-contacts --source import --path D:/客户沟通记录 --search 甲乙 --json

# 生成总结并写 Excel
python cli.py run --source import --path D:/客户沟通记录 \
                  --contacts "甲乙,丙丁" --preset 30d \
                  --out D:/客户沟通总结.xlsx --json

# 全部对象 + 自定义时间范围 + 强制本地引擎
python cli.py run --source import --path D:/客户沟通记录 --all \
                  --start 2026-08-01 --end 2026-08-31 --engine offline

# 解密数据库存档（直接喂 .zip）
python cli.py run --source wxdb --path D:/wechat_archive.zip \
                  --contacts "壬癸信息董事-吃饭群" --preset 30d \
                  --out D:/客户沟通总结.xlsx --json

# 启动图形界面
python cli.py gui
```

`--preset` 可选：`7d` `30d` `this_month` `last_month` `this_quarter` `today`
加 `--json` 输出机器可读结果，便于上游编排。

## 七、常见问题

**Q：点了「加载聊天对象」提示找不到文件？**
检查数据路径是否选对。导入模式要选**文件夹**，不是单个文件。

**Q：导出时报「文件被占用」？**
Excel 正开着这个文件，关掉再导一次。

**Q：总结里说「该时间范围内没有聊天记录」？**
时间范围内确实没有消息。换个范围，或用「近 30 天」先试。

**Q：AI 总结失败了怎么办？**
「智能」模式会自动降级到本地引擎并在结果里标注原因，不会中断整批任务。
结果表格「字数/方式」列会显示这一篇用的是 AI 还是本地。

**Q：总结字数不满意？**
第 ④ 步可以调字数区间，默认 50–200 字。

## 八、平台说明

wxcsm 的 GUI 与引擎（`app.py` / `cli.py` / `core/`）基于 tkinter，本身跨平台（Windows / macOS）。

- **Windows**：当前主要交付形态。双击安装向导即可使用，支持 4.x 加密库直读（wx4）、导入文件、已解密库等数据源。
- **macOS**：同样的 GUI 与引擎基于 tkinter 可运行。macOS 端**不支持 wx4「直读本机微信」数据源**（其为 Windows 微信 4.x 专属机制），但内置样例 / 导入文件 / 已解密库三种数据源以及总结、AI、Excel 导出均可正常使用。

macOS 版由 Windows 开发机上完成兼容化与静态/导入自检。**CI 已在真实 macOS runner 上对构建产物做自动化校验**（`.app` 结构/符号链接/动态库依赖、`.dmg` 挂载校验、`mac_wx4` 模块自检、启动冒烟）；但**尚无真实 macOS 微信环境做过端到端取钥解密验证**，需在装好微信的 Mac 上按 `docs/macOS微信直读_真机步骤.md` 实跑一次确认。取钥与解密均由内置纯 Python 实现完成，不依赖任何外部第三方组件。

### Windows 打包：改了源码为什么界面没变

**这是本仓库最容易踩的坑，务必先读。** 打好的 `绿泡泡聊天记录总结.exe` 是**某个时间点的快照**，
它把当时的 Python 代码封进去了。改完 `app.py` / `core/` 不重新打包，双击 exe 看到的
**还是旧界面**——而且它不会报错、不会提示，表现就是"新功能不见了"。

更隐蔽的是 `绿泡泡聊天记录总结.bat` 第 12 行：**同目录只要有 `绿泡泡聊天记录总结.exe`，就直接跑它、
永远碰不到源码**。所以在这个开发目录里，exe 会一直遮住你的改动。

**怎么立刻确认自己跑的是哪个版本**：窗口标题栏写着

```
绿泡泡聊天记录总结  v2.2.0（打包版）     ← exe，要用就得重新打包
绿泡泡聊天记录总结  v2.2.0（源码版）     ← 直接跑 app.py，改动立即生效
```

版本号在 `core/__init__.py` 的 `__version__`，**每次功能上线都要递增**；
`打包版/源码版` 由 `sys.frozen` 判断。以前版本号一直写死 1.0.0，所以对着旧包找新功能
时完全无从判断，只能靠猜。

**改了代码想看效果，两条路选一条**：

```bash
# A) 不打包，直接跑源码（改完就生效，开发时用这个）
绿泡泡聊天记录总结.bat        # 前提：先把同目录的 绿泡泡聊天记录总结.exe 移走/改名

# B) 重新打包，让 exe 也带上新功能
pyinstaller wxcsm_app.spec --noconfirm --distpath dist   # 产出 dist\绿泡泡聊天记录总结.exe
copy dist\绿泡泡聊天记录总结.exe 绿泡泡聊天记录总结.exe                        # 同步根目录那份（.bat 优先跑它）
python make_installer.py                                 # 产出可分发安装包
```

> 新增 `core/` 下的模块时，记得加进 `wxcsm_app.spec` 的 `hiddenimports`，
> 否则打包产物可能缺模块、一启动就崩。

### macOS 打包与运行

- **直接运行**：`python3 app.py`（需带 tkinter 的 python3，macOS 系统自带）。
- **打包成 .app / .dmg**：`pip3 install --user pyinstaller` 后执行 `python3 make_macos.py`（加 `--dmg` 额外产出 dmg）。
- **校验产物**：`python3 verify_macos.py`（可选 `--require-dmg`、`--no-launch`）。会检查 `.app` 内符号链接与权限位是否完好、`CFBundleExecutable`/`CFBundleIdentifier` 是否正确（bundle id 须为反向 DNS 的 ASCII 形式）、二进制架构是否与宿主兼容、非系统动态库依赖能否解析、`.dmg` 能否 `hdiutil verify`/挂载且卷根 `Applications` 是软链、`mac_wx4` 在真 Darwin 上能否 import 且注册进数据源列表，并尝试拉起 `.app` 观察是否秒退。
- **自动构建 + 自动校验（无需本机 Mac）**：推送到 GitHub 后由 `.github/workflows/build-macos.yml` 在 macOS runner 上构建并校验，从 Actions Artifact `wxcsm-macos` 下载。
- **下载物怎么选（重要）**：选 **`.dmg`** —— 它是自包含磁盘映像，符号链接与权限位都完好。Artifact 里的东西会被打包成 zip，而 **zip 不保留符号链接/权限位**，所以不要用从 zip 里解出的 `.app` 目录（会启动失败）。若需要 `.app` 本体，用同一 artifact 里的 `绿泡泡聊天记录总结.app.tar.gz`（tar 保留符号链接）。
- **Gatekeeper**：未签名 .app 首次打开会被拦截，右键 →「打开」放行一次，或执行 `xattr -dr com.apple.quarantine 绿泡泡聊天记录总结.app`。
- **卸载**：把 .app 从 `应用程序` 拖到废纸篓即可。
- 详见 `docs/macOS版本说明.md`。
